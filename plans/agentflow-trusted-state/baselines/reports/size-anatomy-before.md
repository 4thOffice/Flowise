# Token Size Anatomy, `before/` (Task 02)

- **Input**: `traces/before/` (Task 00b, built from `99e8d4b0`), every mode, 131 tokens. Field meanings and readers: [field-inventory.md](../../field-inventory.md).
- **Regenerate**: `node plans/agentflow-trusted-state/baselines/analyze-token.mjs --markdown plans/agentflow-trusted-state/baselines/reports/size-anatomy-before.md` rewrites everything below the summary. Other options: `--modes`, `--scenarios`, `--detail S01,S07`, `--json <file>`, `--list-paths`, `--check-inventory`.
- **Method**: a path's cost is what deleting every instance of it saves (`raw(token) − raw(token without it)`, same for gzip and base64), measured inside the nested `executionData` string with its escaping. Gzip and base64 are recomputed and match the capture for every token.

## Summary

1. **Node records are the token.** `previousExecution.executionData` is 91–99% of the raw bytes of every M1 token (section A); history is 1–8%. On finished turns `data.input.messages` alone is 82–96% of the gzip bytes (section C).
2. **Size follows node runs, not conversation length.** Each LLM/Agent/Condition Agent run stores its ~41 KB prompt once (section D: sentinel copies = prompt-bearing runs), so S09 (5–7 runs per turn) is 215–301 KB raw / 60–82 KB base64 from its first turn, while S01 grows only 0.4–1.7 KB raw per turn (history plus the history copy inside the Agent's prompt).
3. **Stopped tool approvals store the prompt three times**: the record's `input.messages`, `output.humanInputAction.data.input.messages` and the history `action` string (S07 t2/t4, S08 t1: 3 sentinels, 131.6–136.0 KB raw). The prompt exceeds gzip's 32 KiB window, so each copy costs 8.3–8.8 KB gzip / 11.0–11.7 KB base64 (section E, S07 t2): the stopped token is 38.9–39.6 KB base64 against 14.9–16.0 KB on finished turns. HumanInput stops copy the history instead of the prompt (S06 t1: 0.7 KB per copy), which grows with the conversation.
4. **Resume chains accumulate records** (F09): S06 goes 47.1 → 93.3 → 133.0 KB raw over t1–t3 (4 → 7 → 7 records, 1 → 2 → 3 prompt copies) and drops back on the next question (t4: 51.2 KB).
5. **History messages are mostly metadata.** S01 t5 holds 10 messages in 3.8 KB raw; `{role, content}` alone is ~1.0 KB (at t3, `content` is 0.47 of 2.3 KB). Ids, chat/session ids, dates, `executionId` and `chatType` cost ~280 B per message; DB-mode messages add `null` columns.
6. **State is small here**: one copy per record, 0.03–0.15 KB per token in these flows; it scales with records × state size in flows with large state.
7. **History + state only** (`{history: [{role, content}], state}`, the TS10 lower bound, not the Task 04 design) is 0.15–1.1 KB raw and 0.2–0.7 KB base64 for the last turn of every M1 scenario, against 14.3–82.0 KB base64 today (section A).
8. **DB mode also writes tokens** and never clears `action` in their history: S07 M3 reaches 180.9 KB raw at t4 (4 prompt copies), and at t6 history is still 67% of its 139.3 KB (section A).
9. **Envelope** (`previousExecution` without records): 0.29 KB in every token.

### S01 in detail

Start → Support Agent (all-messages memory, Calculator, Current DateTime); 5 turns, t3 calls the calculator.

- Base64 grows 14.5 → 15.7 KB, gzip 10.8 → 11.7 KB, raw 45.0 → 48.7 KB over t1–t5 (section B). History grows 0.78 → 3.8 KB raw (+2 messages per turn); the Agent prompt copy grows 40.8 → 41.8 KB (it holds the same conversation as role/content pairs).
- The Agent record's `input.messages[].content` (system prompt + history) costs 40.8 KB raw / 9.4 KB gzip / 12.5 KB base64 at t1 (section E): 87% of the gzip bytes. Everything else is below 1.3 KB: outputs, `availableTools` (0.64 KB), `agentModelConfig` (0.54 KB), history. The t3 calculator trace (`output.usedTools`, `data.chatHistory[].additional_kwargs.usedTools`, history `usedTools`) is under 0.3 KB per copy.
- Same shape in every token mode (M1, M1-internal, M1-reqflag, M2, M3-envflags: 48.7–49.0 KB raw at t5); M3 is 50.7 KB because its history messages carry DB columns.

### S07 in detail

Start → Ops Agent (memory; Calculator needs approval); turns: normal → stop → proceed → stop → reject + feedback → normal.

- Finished turns: 14.9–16.0 KB base64, one prompt copy, like S01.
- Stopped turns t2/t4: 38.9 / 39.6 KB base64, 29.2 / 29.6 KB gzip, 133.2 / 136.0 KB raw. Deleting any one of the three prompt copies saves 8.3–8.6 KB gzip (section E); the history `action` (43.0 KB raw) is JSON in a JSON string, escaped twice, and carries `agentModelConfig.FLOWISE_CREDENTIAL_ID`.
- Resume turns t3/t5 return to one copy (the resumed Agent record replaces the stopped one, and the cleared `action` leaves `"action":null`).
- TS-O1 baseline: the pending data a tool-approval resume reads today is `humanInputAction.data.input.messages` = 41.5 KB raw / ~8.6 KB gzip at t2; Task 03 measures what can be dropped from it.
